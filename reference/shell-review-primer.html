Reading Shell Diffs

What the command actually checks — the skill that catches silent gaps.

Agent-written shell tools fail quietly: the command looks right, the verification passes, and the gap hides in what the command never inspected. The review question is always the same: what does this line actually cover, and what does it miss?

Clean/dirty checks: what each one sees

Command (quiet variants)SeesMisses
git diff --quiet Unstaged edits to tracked files Staged edits · untracked files
git diff --cached --quiet Staged edits only Unstaged edits · untracked files
git status --porcelain Everything: staged, unstaged, untracked Nothing — empty output means clean
git status --porcelain -uno Staged + unstaged (tracked only) Untracked files

Rule of thumb: if a tool claims “clean or dirty,” it must mean git status --porcelain. Anything narrower is a spec gap waiting to happen (this was defect #3 in the Lesson 0006 drill).

Porcelain formats worth recognising

OutputLooks likeWatch out for
git status --porcelain ?? new.sh · M file · M file Two columns: staged first, unstaged second. ?? = untracked.
git worktree list --porcelain branch refs/heads/dsv41fmax Full refs. Strip with ${x#refs/heads/} (defect #2).
git branch --show-current dsv41fmax Empty on detached HEAD — handle or declare out of scope.

Silent-failure patterns to hunt in review

  • 2>/dev/null — hides the error message; the exit code still lies onward.
  • || true — failure becomes success.
  • || echo clean — failure becomes a claim. The worst kind.
  • Missing set -euo pipefail — a failing command mid-script doesn’t stop it. -e: exit on error · -u: error on unset variables · -o pipefail: a pipeline fails if any stage fails.
  • if cmd; then A; else B; fi — check which branch means success. Exit 0 = “no differences” for --quiet checks, which inverts naive reading.
  • Unquoted expansions — $var with spaces or empty splits into the wrong args.

The three questions for any shell tool

  1. What does it claim to check? Find the sentence in the brief or comment.
  2. What does the exact command cover? Match it against the first table above.
  3. What happens when the command fails? Follow the else and every ||.
Worked example

The Lesson 0006 drill’s fleet-summary.sh used git -C "$path" diff --quiet 2>/dev/null: it missed staged and untracked changes (question 2) and hid its own errors (question 3) — while its rationale claimed “matching repo-state.sh semantics.” Three questions, thirty seconds.
