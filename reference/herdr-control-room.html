Reference · Parallel Agent Orchestration

The herdr Control-Room Card

Run a fleet of coding agents from one screen. Verified against herdr 0.8.2 and your config on 2026-10-05.

Concept model

LayerWhat it isUse it for
SessionPersistent background server owning the terminals.You need exactly one. It survives closing the window.
WorkspaceProject-level container; agent state rolls up here.One per repo or investigation.
TabA layout of panes inside a workspace.Separate views: agents · review · logs.
PaneA real terminal, splittable and persistent.One agent per pane = one visible worker.
AgentA coding CLI herdr recognizes in a pane.Its state appears in the sidebar automatically.

Agent states: the sidebar is your review queue

StateMeaningYour move
workingActively running.Leave it alone; review something else.
blockedWaiting on you (approval, question).Jump to it now — it’s burning time.
idleFinished its turn, nothing running.Review its output, or give the next brief.
doneCompleted and not yet viewed (rollup).Open the pane; the flag clears.

The sidebar rolls state up: a blocked agent marks its tab and workspace blocked. Scan the workspace names first, panes second.

Your keys (prefix = ctrl+space)

Panes

  • Split right: prefix v · alt+shift+enter
  • Split down: prefix h · alt+enter
  • Focus: ctrl+alt+arrows
  • Resize: ctrl+alt+shift+arrows
  • Zoom / unzoom: prefix z
  • Close pane: prefix x · alt+esc

Everything else

  • New tab: prefix c · switch: alt+1..9
  • Next / prev workspace: alt+↓ / alt+↑
  • Detach (everything keeps running): prefix d
  • Live binding list: prefix ?
  • Reload config: prefix q

Mouse works too: click to focus, drag borders to resize, right-click for menus. Keybindings mirror the Omarchy tmux config on purpose — one muscle memory, two tools.

The loop

StepYou doProve it
1 · BriefWrite a task with acceptance criteria and the verification command.“Done” has a definition.
2 · DelegateOne pane, one agent, one brief. Launch all, then step back.Sidebar shows working.
3 · WorkDo your own work. Do not spectate.—
4 · ReviewRead the diff, run the verification, check side effects.The command passes; nothing else changed.
5 · AcceptMerge / keep / discard. Clear the pane for the next brief.Review queue empty.
The Rule

Parallelize a task only when it is independent (no shared files or interfaces in flux), precisely specified, machine-verifiable, and low-stakes. Fix whichever leg is missing before adding agents.

Review with hunk

CommandReviews
hunk diffUncommitted changes in the working tree
hunk diff --stagedExactly what you’re about to commit
hunk diff <base> <branch>Everything a branch adds — review before merging
hunk show · hunk logLast commit · repository history

Aliases: hdw = hunk diff --watch (live review while agents work); hsa = diff against the empty tree (every change). Built for agent-authored changesets; --agent-context reads a JSON rationale sidecar — claims to verify, not evidence.

Review moves

  1. Intent first — brief, then git diff --stat; scope surprises end the review early.
  2. Verify before inspect — run the acceptance command; red goes back.
  3. Overview → files → lines — hunk sidebar first; stratify risk.
  4. Read risk-first — deletions, changed tests, swallowed errors, new deps, invented APIs.
  5. Run it, don’t just read it — execute an edge case you chose.

Fleet ops

  • WIP limit: cap in-flight agents at what you can review — start at three. Review bandwidth, not CPU count.
  • Triage order: blocked first → idle/done review → working leave alone.
  • Blocked drill: --auto (alias c) suppresses permission asks; plain opencode asks on external-directory writes. permission.asked → sidebar blocked.

Skills (loaded at session start): herdr --skill > ~/.agents/skills/herdr/SKILL.md · ln -sf "$(hunk skill path)" ~/.agents/skills/hunk-review/SKILL.md

Subagents (opencode)

  • Where: global ~/.config/opencode/agents/ · project .opencode/agents/ (filename = agent name).
  • Invoke: @name in a message; primary agents can also call them via the task tool.
  • Read-only reviewer: mode: subagent, edit: deny, granular bash allow-list.
  • Child sessions: Leader+Down to enter · Right/Left to cycle · Up to return. Not in the herdr sidebar.
  • Note: opencode agent create is currently broken here (x-opencode-session routing error) — write the markdown directly.

When something looks wrong

  • Agent state wrong? herdr agent list, then herdr agent explain <target>.
  • linked_worktree_source when creating a worktree? Worktree actions start from the repo’s parent workspace. Run from there, or add --cwd <main-checkout> (keep --base <your-branch>).
  • Keybinding does nothing? The terminal or Hyprland ate the chord — check prefix ? and herdr.dev/docs/keyboard/.
  • Server weirdness? herdr status; logs live in ~/.config/herdr/.
  • Docs drift: verify against herdr --version — this card is v0.8.2-era.
